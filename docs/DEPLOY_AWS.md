# Deploying on AWS

Same shape as [DEPLOY.md](DEPLOY.md), with managed pieces: Caddy and the API run in Docker on one EC2 instance; Postgres is RDS; private files go to S3. Everything is one CloudFormation stack: `deploy/aws/nakama.yaml`.

```
internet -> Caddy (80/443) -> api (uvicorn) -> RDS Postgres 16 (private, SSL)
              EC2 t3.small, Elastic IP          S3 bucket via the instance role
```
No SSH: use SSM (`aws ssm start-session --target <instance-id>`). The database password and `SECRET_KEY` are generated by Secrets Manager and read on the instance at deploy time; they never appear in git, chat or EC2 user-data.

## First time
```bash
aws cloudformation create-stack --stack-name nakama --capabilities CAPABILITY_IAM \
  --template-body file://deploy/aws/nakama.yaml \
  --parameters ParameterKey=VpcId,ParameterValue=<vpc> ParameterKey=InstanceSubnetId,ParameterValue=<subnet> \
               ParameterKey=DbSubnetIds,ParameterValue='"<subnet-a>,<subnet-b>"'
aws cloudformation wait stack-create-complete --stack-name nakama
```
Point a DNS A record at the `ApiEip` address (stack outputs show it), then deploy. Without a domain the stack's `ApiUrl` (an `sslip.io` name) works.

## Ship a version
```bash
SITE_ADDRESS=api2.example.com AWS_PROFILE=default deploy/aws/deploy.sh   # SITE_ADDRESS is optional
```
It packs the working tree, uploads it to the bucket, and runs `docker compose up -d --build` on the instance through SSM: build, `alembic upgrade head`, restart, then a health check. The last 3 releases stay in `/opt/nakama/releases`. **Roll back** by checking out the previous commit and running the script again. Migrations must stay additive (see ONBOARDING).

## First owner account
Interactive, so run it in an SSM session:
```bash
cd /opt/nakama/current/deploy/aws && docker compose exec api python -m app.cli create-owner
```

## Backups
- **Database:** RDS automated backups. The free plan caps retention at 1 day; set `BackupRetentionPeriod` to 7+ after upgrading. A stack delete keeps a final snapshot.
- **Media:** `/srv/nakama/media` on the instance disk is copied to `s3://<bucket>/media-backup/` nightly (cron). Restore by syncing it back.
- Test a restore before you rely on it.

## Cost (ap-southeast-2, rough)
t3.small about $19, db.t3.micro about $16 plus 20 GB storage, public IPv4 about $4: roughly $40-45 a month.

## Not done yet
Multi-AZ database, a load balancer, alarms beyond auto-recover, and cost alerts. Add them when downtime or spend starts to matter.

## Tear down
`aws cloudformation delete-stack --stack-name nakama`. The S3 bucket is kept on purpose (empty and delete it by hand); the database leaves a final snapshot.
